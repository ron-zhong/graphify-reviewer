# Graphify Reviewer

> Autonomous agentic code review for VS Code — integrating **Claude Code**, **Graphify**, **SonarQube CLI**, and **Nexus IQ CLI** into a unified review pipeline.

## End Goal

Trigger **autonomous agentic code review** whenever developers commit code from Claude Code. A hook (e.g., a Claude Code `post-commit` / stop hook) will invoke this tool so that Claude Code, Graphify, SonarQube CLI, and Nexus IQ CLI all work together: the extension handles background scanning and patch drafting, while the developer stays in full control of the final review.

## Original Project Prompt

This project was generated from the following specification:

> You are an expert VS Code extension developer. Your task is to build a CLI tool and a VS Code extension with UI that integrates SonarQube, Nexus IQ, Graphify, and Claude Code into a unified code review tool. The architecture should ensure that the extension handles the background scanning and patch drafting, leaving the developer in full control of the final review.
>
> ### 1. Architecture & Data Flow
> - **Scanner Runner**: Executes SonarQube, Nexus IQ, and Graphify CLIs using `child_process.exec`.
> - **Diagnostics Mapper**: Translates CLI JSON outputs into editor warnings using `vscode.DiagnosticCollection`.
> - **Remediation Actions**: Triggers Claude Code with AST context to generate fixes using `vscode.CodeActionProvider`.
> - **Vulnerability Explorer**: Surfaces a workspace-wide view of technical debt using `vscode.TreeDataProvider`.
>
> ### 2. Configuration (package.json)
> - `activationEvents`: Trigger on `onStartupFinished` or specific language files (`onLanguage:csharp`, `onLanguage:java`, `onLanguage:python`, `onLanguage:typescript`).
> - `contributes.configuration`: Expose settings for users to define the absolute paths to their CLIs if they are not in the system PATH: `graphifyReviewer.claudePath`, `graphifyReviewer.sonarPath`, `graphifyReviewer.nexusIqPath`, and `graphifyReviewer.graphifyPath`.
> - `contributes.commands`: Register a manual trigger (e.g., `graphifyReviewer.runScans`).
>
> ### 3. Core Component Modules
> - **The Orchestrator (`src/runner.ts`)**: Triggers `graphify update .` to ensure the AST graph is current. Executes `sonar-scanner` and `nexus-iq-cli`, passing flags to ensure the output is written to local JSON files (e.g., `.scanner-reports/sonar.json`). Handles execution timeouts and graceful error recovery if a CLI is missing.
> - **The Diagnostics Provider (`src/diagnostics.ts`)**: Watches the output JSON files generated by the Orchestrator. Parses the file paths and line numbers from the SonarQube and Nexus IQ reports. Maps these findings to `vscode.Diagnostic` arrays and pushes them to a `vscode.DiagnosticCollection`.
> - **The Code Action Provider (`src/codeActions.ts`)**: Implements `vscode.CodeActionProvider`. When a developer clicks the lightbulb icon over a generated diagnostic, it surfaces a QuickFix titled "Fix with Claude Code.". Executing the fix spawns a Claude Code CLI process and dynamically constructs a prompt containing the specific diagnostic details and the cross-file dependency context extracted from `graph.json`.
>
> ### 4. Execution Plan
> 1. **Scaffolding**: Generate the `package.json` with the required contributes (settings for CLI paths, commands, and activation events). Generate the `extension.ts` entry point.
> 2. **CLI Orchestrator**: Create `src/runner.ts`. Implement a `child_process` wrapper that runs `sonar-scanner` and `nexus-iq-cli` to output JSON reports, and `graphify update` to generate `graph.json`.
> 3. **Diagnostics**: Create `src/diagnostics.ts`. Parse the generated JSON files and map them to `vscode.Diagnostic` objects so they appear as squiggly lines in the active editor.
> 4. **Code Actions**: Create `src/codeActions.ts`. Implement a `CodeActionProvider`. When a diagnostic is targeted, provide a 'Fix with Claude Code' Quick Fix that passes the diagnostic details and the `graph.json` context to the Claude Code CLI.
> 5. **Tree View (Optional)**: Create `src/treeView.ts`. Implement a `TreeDataProvider` to display all parsed vulnerabilities in a dedicated sidebar panel.

## Components

This repo ships two deliverables over one shared scan engine (`src/core/`, vscode-free):

1. **CLI tool** (`graphify-reviewer`) — run scans and render markdown reports from any terminal or CI pipeline. Developers can trigger scans manually without opening VS Code.
2. **VS Code extension** — a richer UI/UX over the same engine: manual scan command, squiggly diagnostics, "Fix with Claude Code" quick fixes, a vulnerability explorer sidebar, and the scan report rendered as a markdown preview.
3. **Claude Code hook** *(planned)* — triggers the pipeline autonomously whenever code is committed from Claude Code.

## CLI Usage

```bash
npm install -g .          # or: npx graphify-reviewer

# Run all scanners, write .scanner-reports/*.json + report.md
graphify-reviewer scan --cwd /path/to/workspace

# Re-render the markdown report from existing JSON reports
graphify-reviewer report --cwd /path/to/workspace
graphify-reviewer report --print            # to stdout

# Point at CLIs that are not on PATH
graphify-reviewer scan --sonar /opt/sonar-scanner/bin/sonar-scanner \
                       --nexus-iq /opt/nexus-iq-cli.jar \
                       --graphify /usr/local/bin/graphify
```

Environment overrides: `GRAPHIFY_REVIEWER_CLAUDE_PATH`, `GRAPHIFY_REVIEWER_SONAR_PATH`, `GRAPHIFY_REVIEWER_NEXUS_IQ_PATH`, `GRAPHIFY_REVIEWER_GRAPHIFY_PATH`.

## Configuration

| Setting | Description |
| ------- | ----------- |
| `graphifyReviewer.claudePath` | Absolute path to the Claude Code CLI (if not in PATH) |
| `graphifyReviewer.sonarPath` | Absolute path to `sonar-scanner` (if not in PATH) |
| `graphifyReviewer.nexusIqPath` | Absolute path to the Nexus IQ CLI (if not in PATH) |
| `graphifyReviewer.graphifyPath` | Absolute path to the Graphify CLI (if not in PATH) |

## Commands

| Command | Description |
| ------- | ----------- |
| `graphifyReviewer.runScans` | Manually run all scanners (Graphify, SonarQube, Nexus IQ) |
| `graphifyReviewer.openReport` | Open the latest scan report (`report.md`) in a markdown preview |
